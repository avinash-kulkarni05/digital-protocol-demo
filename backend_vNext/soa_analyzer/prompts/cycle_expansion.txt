Task
Analyze EVERY encounter above. For each one, decide whether it needs cycle expansion based on the protocol context and the decision rules below. Return a decision for ALL encounters, not just the ones with obvious cycle patterns.

Contextual Decision Rules

1. Mathematical Delta Inference
   If visits use absolute days (e.g., Day 1, Day 22, Day 43) rather than cycle labels, calculate the interval (e.g., 21 days = Q3W) to infer a cyclic pattern. Cross-reference with the dosing context above to confirm.

2. Cross-Sectional Validation
   Use the PROTOCOL CONTEXT above (especially dosing schedules and study drug sections) as the master source of truth. If the dosing text specifies a frequency (e.g., "Every 3 weeks for 35 cycles"), expand to that count even if the table header is shorthand.

3. Baseline-Cycle 1 Linkage
   Do NOT automatically skip "Baseline" or "Screening." If Baseline timing matches "Cycle 1 Day 1," set shouldExpand: false but note this linkage in the rationale. If Screening has sub-timepoints (Hour 0, Hour 6) that repeat across cycles, it MAY need expansion.

4. Utility Filtering
   Only expand days involving site-based procedures, labs, or PROs. Do not expand "empty" home-dosing days unless a specific assessment (like a diary or PK sample) is required on those days.

5. Calculated Tail Resolution
   For open-ended patterns ("Cycle 4 and Subsequent", "Until progression"):
   - FIRST, exhaustively check the protocol context for ANY duration signal: treatment duration, primary endpoint timeline, number of planned cycles, study duration, maximum treatment period, or any cap mentioned in footnotes or arm descriptions.
   - If you find ANY duration signal, calculate max cycles and expand. Set isCalculatedTail: true and explain your math in the rationale.
   - If no explicit duration is found, apply common oncology conventions based on the therapeutic area and regimen: typically 12-24 cycles for Q3W regimens, 6-12 for Q6W, 24-52 for weekly. Use the study phase and disease context to calibrate.
   - ONLY set requiresHumanReview: true if you truly cannot find any duration signal AND no reasonable convention applies. This should be rare — most protocols provide enough context to infer a reasonable expansion.
   - Check the DURATION SIGNALS section in PROTOCOL CONTEXT for pre-extracted duration data.

6. Linear Visit Protocols
   Some protocols (especially PK studies, Phase 1) use Day-based naming with no cycle labels at all. Use the dosing frequency from protocol context to determine whether Day 1, Day 8, Day 15 etc. represent a repeating cycle or are genuinely distinct one-time visits. If the protocol says "BID dosing in 28-day cycles," then Day 1 and Day 29 are the same day-in-cycle across 2 cycles.

7. Single-Occurrence Structural Visits
   Visits like "End of Treatment," "Early Termination," "Informed Consent," "Randomization," and "End of Study" are almost always single-occurrence. Set shouldExpand: false for these unless the protocol context explicitly indicates otherwise.

8. Multi-Timepoint Visit Awareness (CRITICAL)
   Encounters with a `timingModifier` set and a shared `parentVisit` are sub-visit timepoints (e.g., hourly PK samples within one visit day), NOT separate cycles or separate visit days. Do NOT count them as evidence of cycling. Treat all timepoints under one parentVisit as a SINGLE visit day. Refer to the TIMEPOINT GROUPING section in PROTOCOL CONTEXT for the grouping summary. Only treat them as repeating if PROTOCOL CONTEXT explicitly states they repeat across cycles.

Pattern Types
- EXPLICIT_RANGE: "Cycles 1-6" -> [1, 2, 3, 4, 5, 6]
- EXPLICIT_LIST: "Cycles 1, 2, 4" -> [1, 2, 4]
- SUB_CYCLE_SPLIT: "Days 1, 8, 15 of a 28-day cycle" -> Generate triplets per cycle
- WEEK_BASED: "Weeks 1, 4, 8" -> [1, 4, 8]
- FIXED_INTERVAL: "Every 3 weeks until Year 1" -> Calculate count and expand
- INFERRED_CYCLE: [Day 1, Day 29, Day 57] -> Recognize interval; expand as cycles
- AT_EVENT: "Until progression" -> shouldExpand: false, requiresHumanReview: true
- NO_EXPANSION: Single-occurrence visit -> shouldExpand: false

CRITICAL RULES:
- Return a decision for EVERY encounter, including ones you choose NOT to expand
- For encounters you skip, set shouldExpand: false and explain why in rationale
- expandedCycles must be a list of integers (cycle numbers), never empty if shouldExpand is true
- When shouldExpand is true, include suggestedEncounterNames — a map of cycle number (as string) to clean EDC encounter name. Strip grouped references: e.g., "Cycles 2 and 3 Day 1" expanded to cycle 2 should be named "Cycle 2 Day 1", NOT "Cycle 2 - Cycles 2 and 3 Day 1". When shouldExpand is false, omit or set to null.
- CRITICAL: suggestedEncounterNames MUST be globally unique across ALL encounters in the response. If two different original encounters would produce the same expanded name (e.g., "Cycles 2 and 3 Day 1" and "Every 2 Cycles" both expanding to cycle 2), differentiate them by preserving the original encounter's assessment context. For example, "Every 2 Cycles Starting at C2D1" expanded to cycle 4 should be named "Every 2 Cycles - Cycle 4" or "Assessment Cycle 4", NOT "Cycle 4 Day 1" (which collides with the treatment cycle visit). The treatment cycle encounter ("Cycles 2 and 3 Day 1") gets the clean name "Cycle 2 Day 1"; the periodic assessment encounter gets a distinct name.
- For EVERY encounter, compute an absoluteStudyDay — the nominal study day relative to Cycle 1 Day 1 = Day 1. Use cycleLengthDays to compute: (cycleNumber - 1) * cycleLengthDays + dayInCycle. For pre-treatment visits (Screening, Baseline), use negative days (e.g., -28 for Screening). For terminal visits (End of Treatment), use maxCycle * cycleLengthDays + 1. For timed follow-up (e.g., "30 Days After Last Dose"), add the offset beyond EOT. For recurring follow-up visits, increment sequentially after the last timed follow-up. When shouldExpand is true, include absoluteStudyDays as a map of cycle number (string) to absolute study day. When shouldExpand is false, include absoluteStudyDay as a single integer. These values are used to sort encounters into correct chronological order after expansion.
- confidence must be between 0.0 and 1.0
- If confidence < 0.85, set requiresHumanReview: true
- patternType must be one of: EXPLICIT_RANGE, EXPLICIT_LIST, SUB_CYCLE_SPLIT, WEEK_BASED, FIXED_INTERVAL, INFERRED_CYCLE, AT_EVENT, NO_EXPANSION
- Do NOT wrap the response in markdown code fences
- Return ONLY the JSON object, no preamble or explanation
